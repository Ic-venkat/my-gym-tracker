# Contributing to GymTracker

Thank you for contributing! This project is primarily **AI-assisted** — most code is generated or co-authored with AI coding agents. These guidelines ensure that human and AI contributions stay clean, reviewable, and maintainable.

---

## 🤖 AI-First Development Rules

1. **Read `AGENTS.md` first.** Every AI agent must read and follow the rules in `AGENTS.md` before writing any code.
2. **Human review is mandatory.** All AI-generated code must be reviewed by a human before merging. You are responsible for what you merge.
3. **No hallucinated dependencies.** Do not add packages that don't exist or are unmaintained. Verify on [pub.dev](https://pub.dev) before adding.
4. **Disclose AI usage.** Note in the PR description if code was AI-generated (e.g., *"Scaffold generated by Claude, reviewed and tested by human"*).

## 📏 Pull Request / Merge Request Rules

### Size Limits
| Metric | Limit |
|---|---|
| **Max lines changed** | **300 lines** (excluding generated files and tests) |
| **Max files changed** | **15 files** |
| **Scope** | **One feature, one fix, or one refactor** per MR |

> MRs exceeding these limits will be asked to be split. No exceptions.

### Branch Naming
```
feature/<short-description>    → New features
fix/<short-description>        → Bug fixes
refactor/<short-description>   → Code refactoring
docs/<short-description>       → Documentation changes
test/<short-description>       → Adding or fixing tests
chore/<short-description>      → Build, CI, dependencies
```

### Commit Messages
Follow [Conventional Commits](https://www.conventionalcommits.org/):
```
<type>(<scope>): <short description>

feat(workout): add rest timer with voice notification
fix(voice): handle microphone permission denial on iOS
refactor(database): migrate from sqflite to drift
docs(readme): update installation instructions
test(bloc): add workout_bloc unit tests
chore(deps): update flutter_bloc to 9.x
```

### MR Description Template
Every MR must include:
```markdown
## What
Brief description of what this MR does.

## Why
Why is this change needed? Link to issue if applicable.

## How
High-level approach taken.

## Testing
- [ ] `flutter analyze` passes with zero warnings
- [ ] `flutter test` passes
- [ ] Manually tested on: [Chrome / Android / iOS]

## AI Disclosure
Was AI used? If so, which tool and for what parts?

## Screenshots / Recording
(If UI changes — attach before/after)
```

## 🧹 Code Quality Standards

### Before Submitting
```bash
# 1. Format all code
dart format .

# 2. Analyze for issues
flutter analyze

# 3. Run all tests
flutter test

# 4. Check for unused imports
dart fix --apply
```

All four must pass with zero errors/warnings before submitting a MR.

### Code Review Criteria
Reviewers will check for:
- [ ] Follows architecture rules from `AGENTS.md`
- [ ] No `dynamic` types introduced
- [ ] No business logic in widgets
- [ ] Proper error handling (no empty catches)
- [ ] New public APIs have dartdoc comments
- [ ] Tests included for new BLoCs and repositories
- [ ] File length under 250 lines
- [ ] MR size under 300 lines changed

## 🏗️ Development Workflow

### 1. Pick or Create an Issue
- Check existing issues before creating a new one
- Assign yourself to avoid duplicate work

### 2. Create a Branch
```bash
git checkout -b feature/your-feature-name
```

### 3. Develop Incrementally
- Make small, focused commits
- Run `flutter analyze` frequently
- Test as you go

### 4. Open a Merge Request
- Fill out the MR template completely
- Request review from at least one team member
- Address all review feedback

### 5. Merge
- Squash merge for feature branches
- Ensure CI passes before merging
- Delete the branch after merging

## 📁 Where to Put Things

| Type | Location |
|---|---|
| New feature | `lib/features/<name>/` |
| Shared widget | `lib/core/widgets/` |
| Theme/colors | `lib/core/theme/` |
| Database table | `lib/data/database/` |
| Data model | `lib/data/models/` |
| Repository | `lib/data/repositories/` |
| Voice logic | `lib/voice/` |
| Route definition | `lib/core/router/` |
| Utility function | `lib/core/utils/` |
| Constants | `lib/core/constants/` |
| Unit test | `test/` (mirror `lib/` structure) |
| Decision record | `docs/decisions/` |

---

## 🔒 Security Rules

- Never commit secrets, API keys, or credentials
- Never commit `.env` files (use `.env.example` with placeholder values)
- Never log sensitive user data
- Sanitize all user inputs

---

## 📝 Documentation Rules

- Update `README.md` when adding major features
- Add dartdoc comments to all public classes and methods
- Document architectural decisions in `docs/decisions/`
- Keep `AGENTS.md` updated when patterns or conventions change
